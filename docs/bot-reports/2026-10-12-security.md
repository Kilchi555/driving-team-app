## New findings

### 1. [High] Clients can update tenant branding; staff/admin can update any tenant

- **Location:** `server/api/tenants/branding.post.ts`
- **Attacker:** Authenticated client (same tenant) or staff/admin (any tenant)
- **Controlled input:** `tenantId`, `updateData` (logo URLs, `custom_css`, `contact_email`, `twilio_from_sender`, …)
- **Attack path:** Client POSTs own `tenantId` — no staff/admin role required when tenant matches. Staff in Tenant A POSTs Tenant B’s `tenantId`; `isSystemAdmin` treats staff/admin as system admin and skips tenant isolation, then service-role `tenants.update`.
- **Impact:** Client storefront/SMS-sender takeover; cross-tenant branding defacement / phishing CSS / contact spoofing.
- **Evidence:** `allowedRoles = ['admin','staff','super_admin']`; `isSystemAdmin` bypasses tenant check; no role gate when `userProfile.tenant_id === tenantId`; whitelist includes `custom_css`, `twilio_from_sender`.

### 2. [High] Any authenticated client can read arbitrary same-tenant student credit balances

- **Location:** `server/api/staff/get-student-credits.get.ts`
- **Attacker:** Authenticated low-privilege client in the same tenant
- **Controlled input:** `user_id` query parameter
- **Attack path:** `GET /api/staff/get-student-credits?user_id=<victim>`. Role is loaded unused; returns `balance_rappen` (creates a zero row if missing).
- **Impact:** Same-tenant wallet-balance disclosure.
- **Evidence:** `role` selected unused; query by `user_id`+`tenant_id` with no staff/admin gate.

### 3. [High] Staff `database/query` UPDATE can reassign `tenant_id` via service_role

- **Location:** `server/api/database/query.post.ts`
- **Attacker:** Authenticated staff/admin
- **Controlled input:** `action=update|insert`, `table`, `data.tenant_id`, `filters`
- **Attack path:** Staff UPDATEs a same-tenant `products`/`discounts`/`calendar_tokens`/`locations` row with `data.tenant_id = <victim tenant>`. Filter finds the row via caller tenant; payload still writes attacker `tenant_id` under service_role. INSERT only rejects mismatched `tenant_id` when present (omit bypasses). `calendar_tokens.token` is writable.
- **Impact:** Cross-tenant catalog/discount/calendar-token poisoning; calendar feed token minting.
- **Evidence:** Whitelist includes `tenant_id` and `calendar_tokens.token`; UPDATE does not override `tenant_id` in payload; INSERT check is `safeData.tenant_id && … !== authUser.tenant_id`.

### 4. [High] Unauthenticated check-credentials cron bypass via `x-test-email`

- **Location:** `server/api/cron/check-credentials.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** Header `x-test-email: 1`
- **Attack path:** Call `/api/cron/check-credentials` with only `x-test-email: 1`. Gate is `if (!sendTest && secret !== CRON_SECRET)`, so the test header skips Bearer. Handler emails the platform notification address a credential-rotation report and returns overdue/dueSoon key names.
- **Impact:** Platform inbox spam + recon of which platform credentials are overdue.
- **Evidence:** `sendTest = getHeader(..., 'x-test-email') === '1'`; auth skipped when true; response includes `overdue`/`dueSoon` keys.

### 5. [High] Unauthenticated debug trigger-recalc-queue is a confused deputy for `CRON_SECRET`

- **Location:** `server/api/debug/trigger-recalc-queue.post.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** None (POST trigger)
- **Attack path:** `POST /api/debug/trigger-recalc-queue` with no auth. Comment claims admin/non-prod only, but there is no caller auth or `NODE_ENV` check. Handler reads `CRON_SECRET` and `$fetch`es `/api/cron/process-recalc-queue` with `Authorization: Bearer <CRON_SECRET>`.
- **Impact:** Unauth platform-wide availability-slot recalculation (integrity/DoS) via server-held secret.
- **Evidence:** `getHeader` imported but unused for auth; sibling `generate-slots.post.ts` correctly requires Bearer.

### 6. [High] Year-end finalize cron fails open when `CRON_SECRET` is unset

- **Location:** `server/api/cron/year-end-finalize.get.ts`
- **Attacker:** Unauthenticated user when `CRON_SECRET` is missing/undefined
- **Controlled input:** None (omit Authorization)
- **Attack path:** `GET /api/cron/year-end-finalize` with no Authorization. Gate is `if (secret !== process.env.CRON_SECRET)`. When both are `undefined`, the check does not throw. Job recalculates prior-year staff hours and writes `staff_year_carry_over` for all monthly-salary tenants.
- **Impact:** Cross-tenant payroll/hours integrity corruption if `CRON_SECRET` is misconfigured/absent.
- **Evidence:** `undefined !== undefined` is false; then `recalculateStaffHoursForTenant` + carry-over writes.
