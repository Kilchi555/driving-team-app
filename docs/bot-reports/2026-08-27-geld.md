# Geld-Sicherheitsbericht — Guthaben / Auszahlung / Voucher (2026-08-27)

Read-only audit of credit wallet, withdrawal/payout, and voucher/gift-card credit paths.

**Scope:** `request-credit-withdrawal`, `process-withdrawal-wallee`, `payments/process`, `courses/enroll-wallee`, affiliate payout, staff credit, voucher redeem, `apply-student-credit`, `pending_withdrawal_rappen`.

**Verdict:** All five previously reported issues in this scope remain **still open**. Two **new** confirmed findings (Critical + High). No SQL migration adds atomic freeze/spend enforcement.

### STILL-OPEN-1 — Critical — Frozen withdrawal still spendable

- **Status:** Still open (known #1)
- **Files / logic:**

### STILL-OPEN-2 — High — Concurrent withdrawal requests inflate pending

- **Status:** Still open (known #2)
- **Files / logic:** `server/api/customer/request-credit-withdrawal.post.ts` — check available, insert tx, then `pending += amount` without `WHERE pending = expected` / single-flight lock.
- **Attack story:** Student with CHF 100 available fires two parallel withdrawal requests for CHF 100. Both pass `amount <= available`. Both bump pending → `pending_withdrawal_rappen` can become 200 while balance is 100. Admin export/complete may treat inflated pending as payable.
- **Evidence:**

```58:116:server/api/customer/request-credit-withdrawal.post.ts

    // ... insert credit_transactions ...
        pending_withdrawal_rappen: (creditData.pending_withdrawal_rappen || 0) + amountRappen,
```

### NEW-1 — Critical — Affiliate bank payout ignores withdrawal freeze (double payout channel)

- **Status:** **NEW**
- **Files / logic:** `server/api/affiliate/request-payout.post.ts` selects only `balance_rappen` (no `pending_withdrawal_rappen`); deducts full balance while customer IBAN freeze remains.
- **Attack story:** Same `student_credits` row. User requests customer IBAN withdrawal for full balance (freeze via `pending_withdrawal_rappen`, balance unchanged). Then, if affiliate-enabled, requests affiliate bank payout for the same amount — check uses raw balance and succeeds; balance goes to 0; pending freeze still set. Admin completes customer withdrawal (pays IBAN) **and** processes affiliate payout → school pays ~2× for one wallet.
- **Evidence:**

```59:96:server/api/affiliate/request-payout.post.ts
    .select('balance_rappen')
    // ...

  if (currentBalance < amount_rappen) { /* reject */ }
  // ...
    .update({ balance_rappen: newBalance, ... })
```

Requires affiliate feature for that tenant/user; impact is cash double-payout.

### NEW-2 — High — Staff `/api/credit/use-for-appointment` spends frozen withdrawal balance

- **Status:** **NEW** (additional freeze-bypass vector beyond known #1 customer paths)
- **Files / logic:** `server/api/credit/use-for-appointment.post.ts` — staff/admin only; loads `balance_rappen` only; deducts without subtracting `pending_withdrawal_rappen`. (Sibling `student-credits/use-for-appointment.post.ts` **does** respect freeze.)
- **Attack story:** Student freezes CHF 100 via withdrawal request. Staff (or compromised staff session) applies credit to an appointment via `/api/credit/use-for-appointment` using full balance. Wallet drops; pending withdrawal remains. Admin completes IBAN payout for pending amount → school delivers appointment on credit **and** pays out the same funds.

## Not reported (out of scope / insufficient for medium+)

- `payment-with-negative-credits.ts`: uses non-existent `credits_rappen` column; no live callers found in `server/` — dead/broken helper, not an active exploit path.
- `process-withdrawal-wallee`: disabled (410).

## Suggested fix direction (informational only; no code changed this run)

1. Single source of truth: spend/payout only via `available = balance - pending_withdrawal`, enforced in SQL (`UPDATE … WHERE balance - pending >= :amt` or RPC).
2. Atomic debit: conditional update or `balance_rappen = balance_rappen - :amt` with row lock / `CHECK`.
3. Redeem: mark voucher consumed **first** with `redeemed_at IS NULL` / redemption unique constraint, then credit (or one DB transaction).
4. Align affiliate payout with the same freeze semantics as customer withdrawal (or shared hold column).
