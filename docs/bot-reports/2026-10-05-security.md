## New findings

### 1. [High] Forgeable `x-vercel-cron` bypasses CRON_SECRET on Wallee payment recovery

- **Location:** `server/api/cron/recover-pending-wallee-payments.get.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** Header `x-vercel-cron: 1`
- **Attack path:** Call `/api/cron/recover-pending-wallee-payments` with only `x-vercel-cron: 1`. Handler treats that header as sufficient even when `CRON_SECRET` is set; job syncs Wallee and can update `payments.payment_status` (including `completed` / `paid_at`) across tenants. Also fail-opens if `CRON_SECRET` is unset.
- **Impact:** Cross-tenant payment-status mutation / reconciliation abuse.
- **Evidence:** `isVercelCron = vercelCronHeader === '1'` accepted alongside Bearer; auth block skipped when secret unset.

### 2. [High] Forgeable `x-vercel-cron` triggers platform-wide availability recalculation

- **Location:** `server/api/cron/calculate-availability.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** Header `x-vercel-cron: 1`; optional body `tenant_id` / `staff_id` / `days`
- **Attack path:** POST/GET with forged header; auth is Bearer **or** header. Attacker forces slot rewrite for all active tenants or a chosen `tenant_id`.
- **Impact:** Booking-availability integrity sabotage and compute DoS.
- **Evidence:** Comment documents accepting either CRON_SECRET or `x-vercel-cron`; no-tenant path iterates all active tenants.

### 3. [High] Forgeable `x-vercel-cron` triggers all-staff external calendar sync

- **Evidence:** `if (!isVercelCron && !isValidSecret && !isValidApiKey)` — header alone grants access.

### 7. [High] Any authenticated user can read arbitrary invoice line items across tenants
