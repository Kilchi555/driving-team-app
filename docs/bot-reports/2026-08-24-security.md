## New findings

### 1. [High] Unauthenticated platform analytics dashboard

- **Location:** `server/api/analytics/dashboard.get.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** Optional `timeRange` query (`7d`/`30d`/`90d`/`1y`)
- **Attack path:** `GET /api/analytics/dashboard` with no auth. Handler uses service role immediately and aggregates tenants, users, staff/admins, appointments, payments, and returns `topTenants` with id/name/slug/subscription fields plus activity counts.
- **Impact:** Platform-wide business intelligence disclosure (tenant inventory, plans, growth, operational volumes).
- **Evidence:** No `getAuthenticatedUser` / `requireSuperAdmin`; `getSupabaseAdmin()` then broad selects; response includes `metrics` and `topTenants`.

### 2. [High] Unauthenticated staff invite batch during registration window

- **Location:** `server/api/tenants/invite-staff-batch.post.ts`
- **Attacker:** Unauthenticated user who knows a `tenant_id` created within the last 30 minutes
- **Controlled input:** `tenant_id`, `staff_list[]` (names, attacker email)
- **Attack path:** `POST /api/tenants/invite-staff-batch` with attacker-controlled email. No JWT. After age check, inserts `staff_invitations` via service role, emails invite, and returns `invite_link` (including the raw token) in JSON.
- **Impact:** Privileged staff foothold in a newly registered tenant; invite-token theft even if email delivery fails.
- **Evidence:** Comment documents no JWT; only `created_at` age gate; response includes `invite_link`.

### 3. [High] Unauthenticated Wallee payment-token bind to arbitrary users

- **Location:** `server/api/wallee/save-payment-token.post.ts`
- **Attacker:** Unauthenticated user who can obtain a completed Wallee `transactionId` (own checkout or leaked id)
- **Controlled input:** `transactionId`, `userId`, `tenantId`
- **Attack path:** `POST /api/wallee/save-payment-token` with no auth. Handler loads tenant Wallee secrets, reads the transaction, extracts the payment method token, and inserts into `customer_payment_methods` for the caller-supplied `userId`/`tenantId`.
- **Impact:** Cross-account payment-method binding (plant or steal saved-card linkage) corrupting one-click / stored payment flows.
- **Evidence:** No auth/internal-secret check before `getWalleeConfigForTenant` and service-role insert.

### 4. [Medium] Unauthenticated marketing campaign rename

- **Location:** `server/api/marketing/campaigns/[id]/rename.patch.ts`
- **Attacker:** Unauthenticated user who knows `campaignId` and `tenantId`
- **Controlled input:** Path `id`, body `name`, `tenantId`
- **Attack path:** `PATCH /api/marketing/campaigns/{id}/rename` with no auth; service-role update of `email_campaigns.name`.
- **Impact:** Campaign metadata sabotage under tenant marketing.
- **Evidence:** No auth helper; direct `email_campaigns.update`.

### 5. [Medium] Unauthenticated marketing campaign variant subject mutation

- **Location:** `server/api/marketing/campaigns/[id]/variants.patch.ts`
- **Attacker:** Unauthenticated user who knows a campaign id and variant labels
- **Controlled input:** Path `id`, body `variants[]` (`label`, `subjectOverride`)
- **Attack path:** `PATCH /api/marketing/campaigns/{id}/variants` with no auth; service-role updates of `email_campaign_variants.subject_override` (and related snapshots).
- **Impact:** Alter outbound campaign subject lines (phishing/brand abuse when combined with existing send paths).
- **Evidence:** No auth; loads campaign by id then updates variants via admin client.
