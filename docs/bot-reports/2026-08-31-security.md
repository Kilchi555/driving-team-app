## New findings

### 1. [High] Unauthenticated shop resolve-customer leaks PII and mints onboarding tokens

- **Location:** `server/api/shop/resolve-customer.post.ts`
- **Attacker:** Unauthenticated internet user who knows a tenant UUID and a target email
- **Controlled input:** `tenant_id`, `email`
- **Attack path:** Resolve tenant UUID via public tenant/slug APIs, then `POST /api/shop/resolve-customer` with that `tenant_id` and a victim email. No auth. Service-role lookup returns existing user name/phone/address, or creates a pending guest and returns `metadata.magicLinkToken` (the stored `onboarding_token`).
- **Impact:** Mass PII enumeration for known emails; account takeover of newly planted pending guests via returned onboarding token; CRM pollution.
- **Evidence:** Comment documents no auth for guest checkout; existing-user branch returns phone/street/zip/city; new-guest insert sets `onboarding_token` and returns `magicLinkToken` in JSON.

### 2. [High] Unauthenticated price-calculation email is an open HTML relay

- **Location:** `server/api/booking/send-price-calculation.post.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** `email`, `category`, `totalCost`, `calculationDetails` (raw HTML interpolated)
- **Attack path:** `POST /api/booking/send-price-calculation` with a victim inbox and attacker HTML in `calculationDetails`. No auth. Handler builds HTML with unsanitized `${body.calculationDetails}` and sends via Resend from `noreply@drivingteam.ch`.
- **Impact:** Phishing/spam from a trusted domain; HTML injection in the mail body; outbound email cost abuse.
- **Evidence:** No auth/rate-limit; Resend `emails.send` to `body.email`; `calculationDetails` embedded directly in the template.

### 3. [High] Unauthenticated tenant seed-defaults overwrites feature flags and booking config

- **Location:** `server/api/tenants/seed-defaults.post.ts`
- **Attacker:** Unauthenticated internet user who knows a tenant UUID
- **Controlled input:** `tenant_id`, optional `business_type` / `overwrite_existing`
- **Attack path:** `POST /api/tenants/seed-defaults` with a victim `tenant_id` and optional `business_type` override. No auth. Service role inserts categories/event types/pricing rules and upserts `tenant_settings` feature flags and UI labels from the chosen preset.
- **Impact:** Cross-tenant configuration sabotage (feature flags, labels, booking types/pricing pollution).
- **Evidence:** Handler starts with `readBody` and `getSupabaseAdmin` only; `overrideType` accepted from body; settings upsert on conflict `tenant_id,category,setting_key`.
