## New findings

### 1. [High] Unauthenticated pendencies handle-recurrence creates new tasks across tenants

- **Location:** `server/api/admin/pendencies/handle-recurrence.post.ts`
- **Attacker:** Unauthenticated internet user who knows a recurring pendency UUID
- **Controlled input:** `pendencyId`
- **Attack path:** Attacker `POST`s `/api/admin/pendencies/handle-recurrence` with no auth. Handler uses service role, loads the pendency by id, and inserts a cloned next-due row when `recurrence_type ≠ keine`.
- **Impact:** Cross-tenant operational task pollution/sabotage (pairs with known unauthenticated `update-overdue`).
- **Evidence:** No `getAuthenticatedUser` / `CRON_SECRET`; `getSupabaseAdmin` then `pendencies.insert` copying `tenant_id`, assignee, and recurrence fields from the caller-supplied id.

### 2. [High] Authenticated company-billing manage load/get-default is an IDOR for billing PII

- **Location:** `server/api/company-billing/manage.post.ts`
- **Attacker:** Any authenticated user who knows a victim `userId`
- **Controlled input:** `action=load|get-default`, `userId`
- **Attack path:** Authenticate, then `POST` `/api/company-billing/manage` with `action=load` (or `get-default`) and a victim `userId`. Create/update/delete enforce ownership; load/get-default do not and return `select('*')` billing rows.
- **Impact:** Cross-account company billing PII disclosure (name, email, phone, address).
- **Evidence:** `getAuthenticatedUser` only; load filters `created_by=body.userId` with no caller match; get-default loads the victim default address fully.

### 3. [Medium] Unauthenticated demo email endpoint is an open branded relay

- **Location:** `server/api/demo/send-demo-email.post.ts`
- **Attacker:** Unauthenticated internet user
- **Controlled input:** `email`, `schoolName`, `templateType`, `primaryColor`
- **Attack path:** Attacker `POST`s `/api/demo/send-demo-email` (rate-limited to 3/IP/hour). No auth. `sendEmail` delivers a demo template to the chosen inbox with `senderName=schoolName`.
- **Impact:** Phishing/spam with spoofed school branding; outbound email cost abuse.
- **Evidence:** No auth helper; validation + cache rate limit only; then `sendEmail({ to, subject, html, senderName: school })`.

### 4. [Medium] Any authenticated tenant user can resend arbitrary same-tenant invoices

- **Location:** `server/api/invoices/resend.post.ts`
- **Attacker:** Authenticated low-privilege client in the same tenant
- **Controlled input:** `invoiceId`
- **Attack path:** Client `POST`s `/api/invoices/resend`. Handler requires auth and matching `tenant_id` only (no staff/admin role). Regenerates PDF, emails the billing recipient, sets status to sent, and returns `sentTo`.
- **Impact:** Invoice harassment under tenant brand, billing-email disclosure, and `sent_at`/status corruption.
- **Evidence:** `getAuthenticatedUser` + tenant compare only; no role gate before `sendEmail` / status update.

### 5. [Medium] Unauthenticated get-user-payment-token discloses stored payment-method IDs

- **Location:** `server/api/booking/get-user-payment-token.post.ts`
- **Attacker:** Unauthenticated user who knows `userId` + `tenantId`
- **Controlled input:** `userId`, `tenantId`
- **Attack path:** Attacker `POST`s `/api/booking/get-user-payment-token` with no auth. Service role returns the default/active `customer_payment_methods.id`.
- **Impact:** Payment-method ID disclosure that aids token-binding / one-click abuse chains (pairs with known unauthenticated `wallee/save-payment-token`).
- **Evidence:** No auth; `getSupabaseAdmin`; `select id` by `user_id`+`tenant_id`; returns `{ id }`.
