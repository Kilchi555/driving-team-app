## F-05a — Payments RLS

### Original problem

Live policy `customer_update_own` allowed authenticated clients to UPDATE their own `payments` rows (match via `users.id`), including `payment_status` and other sensitive columns. App JS checks were bypassable via PostgREST.

### Current implementation (live)

| Policy | Cmd | Roles | Notes |
|--------|-----|-------|-------|
| `customer_read_own` | SELECT | authenticated | Own `user_id` only |
| `staff_read_tenant` | SELECT | authenticated | Staff/admin/tenant_admin tenant |
| `super_admin_read_all` | SELECT | authenticated | Checks `role = 'superadmin'` (**typo** vs live `super_admin`) |
| `customer_insert_own` | INSERT | authenticated | `user_id = auth.uid()` (auth id vs `users.id` mismatch — residual) |
| `staff_insert_tenant` | INSERT | authenticated | Tenant staff |
| `super_admin_insert_all` | INSERT | authenticated | Same `superadmin` typo |
| ~~`customer_update_own`~~ | — | — | **ABSENT** (`COUNT=0`) |
| `staff_update_tenant` | UPDATE | authenticated | Tenant staff may update any column in-tenant |
| `super_admin_update_all` | UPDATE | authenticated | `superadmin` typo |
| `service_role_all` | ALL | service_role | Server/webhooks |

RLS enabled on `payments`. No `student_id` column (`NOT APPLICABLE`).

### Who may change what (Data API)

| Actor | SELECT | UPDATE sensitive fields | Notes |
|-------|--------|-------------------------|-------|
| Client (`role=client`) | Own payments | **DENY** (no UPDATE policy) | F-05a closed |
| Staff / Admin / Tenant Admin | Tenant | ALLOW (full row via `staff_update_tenant`) | Intentional product; separate MEDIUM finding if staff must not set `completed` without provider |
| Super Admin | Broken if only `super_admin` in DB | Broken likewise | Residual typo |
| Service role | All | All | Server-only; expected |
| Anon | DENY (0 rows) | DENY | Verified |

### RLS vs API

Security boundary for F-05a is **PostgreSQL RLS** (no customer UPDATE policy). Client composable `usePaymentStatus.ts` still *attempts* client UPDATEs — those fail at RLS (defense in depth). Server/webhook paths use service_role and remain capable of status updates (expected).

### Service role

Bypasses RLS; used by Wallee webhooks, `payments/process`, admin payment ops, etc. Not a F-05 finding while service_role stays server-only.

## F-05b — Reminder Logs RLS

### Original problem

Policies `Enable select/insert for authenticated users` used `auth.role() = 'authenticated'` with no tenant predicate → any JWT could read/write all `reminder_logs` (PII: recipient, body).

### Current implementation (live)

| Policy | Cmd | Rule |
|--------|-----|------|
| `reminder_logs_staff_select_tenant` | SELECT | `tenant_id` non-null AND matches staff/admin/tenant_admin tenant |
| `reminder_logs_super_admin_select_all` | SELECT | `users.role = 'super_admin'` |
| `reminder_logs_service_role_all` | ALL | service_role |
| ~~Enable select/insert for authenticated~~ | — | **ABSENT** |

No authenticated INSERT/UPDATE/DELETE policies.

**Data note:** Live `reminder_logs` = 16 rows, **all `tenant_id IS NULL`**. Policy hides null-tenant rows from staff Data API SELECT. New writers on `main` (`/api/reminders/manage`) stamp `tenant_id`.

### Who may read (Data API)

| Actor | SELECT reminder_logs |
|-------|----------------------|
| Client | **DENY** (no policy) — verified 0 of 16 |
| Staff/Admin | Own tenant only (requires stamped `tenant_id`) |
| Super Admin | All (canonical `super_admin`) |
| Anon | DENY — verified |
| Service role | All |

### Attack vectors tested

| Vector | Expected | Actual | Status |
|--------|----------|--------|--------|
| Client `SELECT * FROM reminder_logs` | DENY / 0 | `visible_rows=0` (16 exist for service_role) | **PASS** |
| Client INSERT reminder_logs | DENY | RLS violation | **PASS** |
| Staff A SELECT all (null-tenant corpus) | 0 visible | `visible_rows=0` | **PASS** |
| Staff A filter `tenant_id = foreign` | DENY/empty | DENY/empty | **PASS** |
| Staff B SELECT tenant A reminders | DENY/empty | `visible_rows=0` | **PASS** |
| Anon SELECT reminder_logs | DENY | 0 rows | **PASS** |
| Staff own-tenant SELECT of **stamped** foreign vs own rows | DENY / ALLOW | **NOT VERIFIED this retest** (no stamped rows; read-only forbids seeding). Prior remediation probe (F-05 fix session) **PASS**. Policy text requires tenant match. | Policy **VERIFIED**; stamped-row probe **NOT RE-RUN** |

### API routes

| Route | Auth | Notes |
|-------|------|-------|
| `GET /api/admin/reminder-logs` | `requireAdminProfile` + `.eq('tenant_id', profile.tenant_id)` | Service role + tenant filter |
| `POST /api/reminders/manage` `log-sent`/`log-failed` | `getAuthenticatedUser` + service_role insert with `tenant_id` stamp | Client Data API writes removed |
| `get-logs` action | Auth required; service_role query by appointment/user **without strong tenant assert** | **Residual** (related R-04 / not original F-05b open RLS) — document only |

Direct Data API is the F-05b boundary and is closed. Unauthenticated manage → Unauthorized.
